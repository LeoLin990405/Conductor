# Task-first interaction

§8.2 asked for interaction centred on task objects. This change makes create, track, and close the task actions. It does not copy a legacy repository. The behaviour extends Conductor's Ticket in `src/server/app/autonomy.py`, `src/server/services/autonomy/task_interaction.py`, and `src/server/services/autonomy/worker.py`, and the Inbox and task pages under `web/src/features/superagent/`.

Create is still `POST /api/v1/autonomy/tasks`. Track is `GET /api/v1/autonomy/tickets/{id}/activity`, a projection of the task, its inputs, and its reports. That projection does not include the worker thread or run id. Close is `POST /api/v1/autonomy/tickets/{id}/close`. An open task is cancelled and stamped closed. A completed or already cancelled task keeps that outcome and only gains the stamp. A second close does not write again. Migration `120_task_close.py` adds `closed_at` and `close_reason` after revision 119 and drops both columns on the way down. Revision 119 is the channel-reply approval migration.

An instruction sent before a worker session exists is stored on the task (`queued_on_task`). The cloud worker launch includes those undelivered instructions and then marks them delivered. A waiting daemon ticket still queues an answer for the daemon. The task page shows the activity, an instruction box that does not require a worker thread, and Close task. The worker stream is an execution log.
