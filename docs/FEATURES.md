# Conductor features in detail

The README has the one-line version of each feature. This page keeps the full details.

- **One intake.** Manual goals, GitHub issue and pull-request comments, cron schedules and Feishu messages all become Tickets in the same pipeline.
- **Durable Ticket lifecycle.** A Ticket is queued, running, waiting, ready, blocked, awaiting clarification, completed, failed, cancelled or archived; switch keeps the thread and worktree, and file handoffs carry a sha256 manifest.
- **Two worker runtimes.** The PTC agent runs Python, MCP tools and subagents in a sandbox; native CLI workers run vendor CLIs in their own sessions and caches.
- **Thirteen native adapters, eleven native Workers.** `src/llms/native_cli/` has adapters for Codex, Claude Code, Cursor, Kimi, DeepSeek DSH, Grok, StepFun, MiniMax (mcode), MiMo, ZCode, GLM (Zhipu), and two text-only ones, Doubao/ARK and MiniMax mmx, which are not registered as native Workers. Gemini and Qwen are PTC-only.
- **Bounded concurrency.** A local daemon runs 1–32 Tickets at once (default 1). `AUTONOMY_MAX_RUNNING_WORKERS` (default 4) also caps the Tickets running across all Workers: a daemon claim and a Cloud Worker launch are counted together under one lock, and a launch that finds no free slot waits queued instead of failing ([`docs/CLOUD-WORKERS.md`](CLOUD-WORKERS.md), "Concurrency"). `NativeAgents` runs at most four tasks per call, and `NATIVE_CLI_MAX_PARALLEL` (default 4) can only lower that.
- **Live Worker output.** A local daemon streams the Codex CLI's visible text and tool names to the server while the CLI runs (app-server token deltas by default; `CONDUCTOR_CODEX_APP_SERVER=0` falls back to completed items only); a turn that ends without a final answer before any visible output is retried once on `codex exec`; `GET /api/v1/autonomy/tickets/{id}/activity/stream` (SSE), the CLI and the TUI follow it and resume after a disconnect. A shared credential scanner checks every event on both sides and ends a run's live text on a hit. Codex only, needs migration 140, `CONDUCTOR_DAEMON_TOKEN_STREAM=0` turns it off, and the scanner is a heuristic, not a guarantee ([`docs/SUPER-AGENT.md`](SUPER-AGENT.md)).
- **Transactional delivery.** Cross-process actions run as durable effects in an outbox with leases, retries and idempotency keys; Postgres advisory locks let multiple backend workers schedule safely.
- **Supervision.** A deterministic watchdog flags stalled queued, waiting and running Tickets, and enqueues a separate Watchdog session to review a stale running worker.
- **Sandbox choices.** Daytona, E2B, Docker and SSH computers for the PTC agent. Local native workers require an OS isolation profile and fail closed without one; cloud autonomous Workers are refused unless the opt-in Docker runtime is enabled (below).
- **Review and merge API.** `conductor review` and `conductor merge` call server routes: review verdicts are durable Postgres rows, and a merge is rehearsed in a temporary worktree, tested, reviewed by a server-run Codex and only then landed with a compare-and-swap `git update-ref` ([`docs/REVIEW-MERGE-API.md`](REVIEW-MERGE-API.md)).
- **Operator surfaces.** REST API, `conductor` CLI, an interactive Super-agent TUI, web console, Electron desktop shell, Agent Plugins bundles, an MCP catalog and a read-only agent fleet view.
